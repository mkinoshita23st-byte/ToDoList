# ToDo App Lv.3 README

## アプリ名
ToDo App Lv.3

## アプリ概要
タスクの追加・削除・編集、Todoリストの閲覧などの基本的な機能をそろえたToDo管理アプリケーション

## 主な機能:

### タスク追加機能
タスク名、未来の期限日、9:00から18:00の5分区切りの制限時間を指定してタスクを追加できます。
タスク名・期限日・制限時間の3つの適切な入力値がそろってないとアラートが出ます。

### タスクの状態切替機能
タスクが完了か未完了かをボタン一つで切り替えられます。

### タスク編集・保存機能
タスク名、期限日、制限時間を再編集できます。
編集中は他の操作をロックします。
保存時にタスク名・期限日・制限時間の3つの適切な入力値がそろってないとアラートが出て、元のタスク内容に戻ります。

### タスク削除機能
不要になったタスクを削除できます。

### 期限切れ判定機能
期限を過ぎたタスクは自動的に無効化され、ToDoリストの下部へ移動し、「期限切れ」ラベルが表示されます。

### タスク件数表示機能
全て、未完了、完了のそれぞれの期限内のタスク件数がリアルタイムで更新・表示されます。

### 検索・絞り込み・並び替え機能
- キーワードによる検索
- 状態（すべて・未完了・完了）による絞り込み
- 追加順・期限の近い順・期限の遠い順への並び替え
上記3つの機能によりToDoリストの表示がリアルタイムに変更されます。

### タスク保存機能
起動時にローカルストレージからタスク配列を取得します。
タスクの追加・編集・削除のたびにローカルストレージの内容を更新します。

## 使用技術
- HTML
- JS
- BootStrap

## データ構造:   
const task={
    id: 0,                  // タスク固有のID
    title: "タスク名",      // タスク名
    completed: false,       // 完了状態（true/false）
    dueDate: "2026-12-25",  // 期限日
    dueTime: "10:05",       // 制限時間
    createdAt: 1711234567890// 作成日時（タイムスタンプ）
}

## 工夫した点

- 見やすいレイアウトの追求
長文のタスク名がレイアウトを崩したりボタン領域を圧迫したりしないよう、CSSの overflow-wrap: anywhere; を活用して適切に折り返し処理を行い、視認性を高めました。

- 誤操作を防ぐボタン・入力欄の制御
編集モード時には他の入力欄やボタンを一時的に無効化する toggleOtherBtns 関数を実装しました。

- 入力バリデーション（アラート設定）
タスクの追加・編集時において、タスク名や期限日、制限時間などの必要な項目がそろっていない場合に適切なアラートを表示し、不正なデータの登録を防止します。

- 期限切れタスクの適切なハンドリング
期限を過ぎたタスクに対して以下の制御を行い、タスク管理の利便性と視認性を向上させました。
・件数表示からの除外
・リストの下部への自動配置
・視覚的に分かりやすい「期限切れ」バッジの表示と、全体が灰色になるスタイリング
・該当タスクに対する操作ボタンの無効化

## 苦労した点

### コードの関数化
前作の「ToDo App Lv.2」をベースに開発を行いましたが、期限日時機能の追加に伴いコードが煩雑になりました。そのため、共通する処理を関数として切り出すリファクタリングを行いました。しかし、適切な引数の設計や、関数がコード全体に与える影響範囲を慎重に考慮しながら書き直す作業に時間を要しました。

### 画面のレイアウト（BootStrapの活用）
独自のCSSファイルを使わず、Bootstrapを使用して仕様書通りの画面構成を再現することを目指しましたが、実装しきれませんでした。次回は、カスタムCSSによる調整からBootstrapのクラスを活用したレイアウト構築へ移行したいと考えています。
